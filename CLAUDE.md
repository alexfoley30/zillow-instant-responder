# Working with Alex on this repo

## How to explain things

Alex is not a programmer. Explain everything in plain English, the way you'd
explain it to someone smart who has never written code.

- No jargon. If a technical word is unavoidable, say what it means in the same
  breath ("a test — a little automatic check that runs and tells you if
  something broke").
- Use comparisons to real, everyday things (email, a filing cabinet, a
  checklist, a receipt) instead of computer concepts.
- Lead with what it means for him and his business: does the robot still email
  renters correctly, did anything break, does he need to do anything.
- Keep file names and code snippets out of the summary unless he asks. Put them
  at the bottom under a "details" heading if they matter.
- Short paragraphs. Say the answer first, then the reasoning.

This applies to every reply, including automated/scheduled runs and pull
request descriptions.

## What this project is

An automatic email assistant. When someone on Zillow asks about one of Alex's
rental listings, this program reads the email and writes back on its own —
answering common questions, offering tour times, and putting confirmed tours on
the calendar. When it isn't sure, it stops and pings Alex instead of guessing.
